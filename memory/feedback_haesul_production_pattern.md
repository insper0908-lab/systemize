`POINT 과학기술 해설.hwpx` (실제 사용 중인 production 해설)을 직접 분석한 출력 패턴. 단순 스켈레톤 템플릿과 다르므로 production 작업 시 이걸 따를 것.

**Why:** 사용자가 실제로 학생들에게 배포하는 해설 형식이 단순 스켈레톤보다 훨씬 풍부함. 같은 형식으로 찍어내야 일관성 유지. 단순 스켈레톤(1-6 styleID)만 보고 작업하면 production 톤·구조와 어긋남.

**How to apply:**

## 1. 전체 구조 (Top → Bottom)

```
[1] 챕터 배너 — "POINT 과학 기술" (paraPrIDRef="31")

[2] 지문 섹션 시작:
    - 지문 타이틀 — "YYYY_MM 지문제목" (paraPrIDRef="51")
    - "DAY" 마커 (paraPrIDRef="0")

[3] 전체 지문 원문 — 통째로 한 번 (paraPrIDRef="62" 단락 단위)
    각 원문 문단을 그대로 옮겨놓은 블록

[4] 문단별 깊이 분석 (1문단 ~ N문단 반복):
    - "N문단" 헤더 (paraPrIDRef="60" 또는 "67")
    - "N문단" 사본/북마크 (paraPrIDRef="0")  ← 같은 텍스트 한 번 더 (사이드바용)

    [첫 문단 한정]
    - "* POINT 실전적 생각" (paraPrIDRef="68")
    - "기의 독해, 기둥 잡기" (paraPrIDRef="68")

    [각 문장 단위 반복]
    - 원문 한 문장 (paraPrIDRef="62")
    - ● 기의 변환 (paraPrIDRef="67" 또는 "69")
    - ● 기의 변환 추가 라인 (필요 시)
    - 흐름 코멘트 / 친근한 톤 메모 (paraPrIDRef="67")
```

## 2. 문장별 분석 패턴 (가장 중요)

각 원문 문장 뒤에 붙는 **● 해설 + 흐름 코멘트** 패턴 — 실제 예시:

```
[원문 62] 한편, 큰 소리로 인해 작은 소리가 들리지 않는 현상을 차폐라고 하며 차폐를 일으키는 큰 소리를 차폐음이라 한다.
[해설 67] ● 차폐: 안들리는 현상 (원인: 큰소리 = 차폐음)
[흐름 67] 큰놈(차폐음) 때문에 작은 놈 안들리네 ㅇㅋㅇㅋ
[흐름 67] 근데 흐름 놓치지 말자.
[흐름 67] 우리 뭐 읽는건데?
[흐름 67] 아 압축 제거 할건데, 제거 기준(최소가청강도, 차폐)
[흐름 67] 아 지금 안들리는 것들 제거 압축 하겠네. 전송하려고.
[흐름 67] 최소가청강도, 차폐 둘다 안들리는 기준값
```

**관찰:**
- ● 라인은 보통 1~3개. 핵심 기의를 압축
- 흐름 코멘트는 **여러 줄**로 길게 풀어서 — 자기 대화하듯, 학생에게 말 걸 듯
- "근데 흐름 놓치지 말자" / "우리 뭐 읽는건데?" / "아 ~겠네" 같은 자문자답 패턴 자주 사용
- 같은 단락 내에서 앞뒤 문장 연결 환기 (예: "이 글은, 매체 발명 → 저장법(축음기 시작) 발전")

## 3. 톤 (실제 표현 인용)

- "ㅇㅋㅇㅋ" / "ㅇㅎ" / "근데 몰라도 상관없음ㅋ"
- "수능장에서 꽥!" / "ㅎㅎ"
- "잘들리는 놈 잘들리게, 안들리는 놈 제거"
- "별 거 없네" / "어휘를 알면 기의가 많아진다"
- "*최소 가(가능한) 청(듣기) 강도" 처럼 한자 어휘 풀이도 가끔 곁들임
- 학생 코칭 멘트: "평상시 공부할 때 모르는 어휘를 찾아보는 습관을 만들자"

## 4. 지시대명사 처리 — 실제 예시

```
[원문 62] 이것이 초기 녹음기의 원리인데, 소리를 아날로그 형태로 저장하였고…
[해설 67] ● 이것= 2~5문장= 축음기= 초기 녹음기 = 저장법 START
[해설 67]      = 아날로그
[흐름 67] 지시 대명사 잘 잡으며 읽자.
```
→ "이것"의 원지시 대상을 **여러 단계로 풀어 등호로 연결**. "지시 대명사 잘 잡으며 읽자" 같은 메타 코멘트도 같이 적음.

## 5. 기둥 잡기 박스 (1문단 시작 시 1회)

```
[paraPrIDRef="68"] * POINT 실전적 생각
[paraPrIDRef="68"] 기의 독해, 기둥 잡기
```
**주의:** "기능 잡기"가 아니라 **"기둥 잡기"**.

## 6. 문제 해설 섹션 — 이 예시 파일에는 없음

이 production 파일은 **지문 분석만** 들어있다. 문제 해설은 별도 템플릿/파일에서 처리하는 것으로 추정. 문제 해설을 추가할 때는 사용자에게 형식을 다시 확인할 것.

## 7. 레퍼런스 파일 위치

레포 내 `examples/POINT 과학기술 해설.hwpx` 에 원본 아카이브됨. 의심나면 직접 추출해서 비교.
