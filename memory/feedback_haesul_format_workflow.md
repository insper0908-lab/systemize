수능 국어 해설을 HWPX로 만들 때 따라야 하는 출력 형식과 작업 절차. 사용자가 운영하는 "체계 국어" 해설의 표준 포맷이다.

**Why:** 사용자가 반복해서 같은 형식으로 해설을 찍어내야 하는 작업이라, 매 세션마다 형식·스타일·워크플로를 다시 설명할 필요 없도록 굳혀둠. 템플릿 HWPX의 스타일 ID는 한글 문서 내부 참조라 절대 변경하면 깨짐 — 그래서 "절대 변경 금지" 규칙이 강함.

**How to apply:**

## 1. 작업 순서

1. **문제가 있으면** → 해설 작성 전에 "각 문제 정답 번호 알려주세요" 먼저 묻고 답변 받은 후 진행
2. **정답 확인 후** → 독해 철학(`feedback_korean_reading_principles.md`)에 따라 해설 내용 구성
3. **템플릿 HWPX 복사** → `Contents/section0.xml` 수정 → 새 파일로 저장
4. 출력 경로: `/mnt/user-data/outputs/해설_[지문제목].hwpx`
5. `present_files` 도구로 사용자에게 전달
6. 템플릿 경로는 매 세션마다 사용자가 지정 (과목별로 다른 템플릿 사용)

## 2. 스타일 ID 매핑

**스타일 ID는 템플릿마다 다르다.** 작업 시작 전 항상 해당 템플릿의 `section0.xml`에서 실제 사용된 `paraPrIDRef` 값을 확인하고 거기에 맞춰 작성할 것.

### (a) 단순 스켈레톤 템플릿 (`해설_템플릿.hwpx` 류)
```
styleIDRef="1" → 본문
styleIDRef="2" → 헤더 ([N문단], [문제 N번])
styleIDRef="3" → 원문박스 ((원문 N문장))
styleIDRef="4" → 흐름코멘트 (빨강)
styleIDRef="5" → POINT강조 ("기의 독해, 기둥 잡기")
styleIDRef="6" → 선지 (① ② ③ ④ ⑤ + 근거 + 일치/불일치)
```

### (b) Production 템플릿 (`POINT 과학기술 해설.hwpx` 등)
```
paraPrIDRef="0"   → 작은 마커 (DAY, 문단 헤더 사본)
paraPrIDRef="31"  → 챕터 배너 ("POINT 과학 기술")
paraPrIDRef="49"  → 상단 헤더 (대체)
paraPrIDRef="51"  → 지문 섹션 타이틀 ("2026_09 차폐")
paraPrIDRef="60"  → 문단 헤더 ("1문단", "2문단"…) — 첫 출현
paraPrIDRef="62"  → 원문 (지문 본문 또는 단일 문장 원문)
paraPrIDRef="67"  → 본문 해설 (● 기의 변환, 흐름 코멘트 — 일반)
paraPrIDRef="68"  → POINT 박스 ("* POINT 실전적 생각", "기의 독해, 기둥 잡기")
paraPrIDRef="69"  → 본문 해설 (강조 — 색상/굵기 다른 ● 라인)
```

### 공통 규칙
- `styleIDRef`, `charPrIDRef`, `paraPrIDRef` 등 모든 ID 속성은 **그대로 보존**
- 템플릿이 정의한 ID를 절대 새로 만들지 말고, 기존 단락을 복제하거나 텍스트만 교체할 것

## 3. 출력 구조

### 지문 해설 (문단별)
```
[N문단]                  ← styleIDRef="2"
N문장                    ← styleIDRef="1"
(원문 N문장)             ← styleIDRef="3"
● (기의 변환)            ← styleIDRef="1"
● (기의 변환)            ← styleIDRef="1"
(흐름 코멘트)            ← styleIDRef="4"
```

### 문제 해설
```
[문제 N번]                                    ← styleIDRef="2"
발문 분석: (발문이 묻는 것을 기의로)            ← styleIDRef="1"
선지 분석:                                    ← styleIDRef="1"
① (선지 내용) → O/X                            ← styleIDRef="6"
   근거: [N문단 N문장] "(지문 핵심 기의 변환)"  ← styleIDRef="6"
   → (일치/불일치 설명)                        ← styleIDRef="6"
② ~ ⑤ 동일하게                                ← styleIDRef="6"
정답: ①                                       ← styleIDRef="1"
(지문과 선지의 차이 한 줄 정리)                ← styleIDRef="4"
```

## 4. 본문 표기 규칙

- **허용 기호만**: `●` `→` `=` `+` `[ ]`
  - `=` 동치 / `→` 인과·흐름 / `+` 결합
- **구어체 친근한 톤**: "ㅇㅋㅇㅋ", "~네", "~구나", "흐름 놓치지 말자" 등
- **지시대명사**(이것/그것) 등장 시 → 반드시 원지시 대상 명시
- **지문 밖 어휘 절대 금지** (최우선) — 지문에 한 번도 등장하지 않은 단어는 단 하나도 사용 금지
  - 기의 변환도 지문 표현만: '지용성' X → '지방에 녹는' O / '산화' X → '산소와 결합하는' O
- **기의 없는 기표는 숫자로** — 전문용어/고유명사를 등장 순서대로 1, 2, 3... 으로 대체
  - 예: 프로트롬빈=1, 트롬빈=2 → "1이 활성화 → 2로 전환"
- **POINT 박스** ("* POINT 실전적 생각" + "기의 독해, **기둥** 잡기")는 1문단 `[N문단]` 헤더 **바로 앞에 단 1회만** (이미 템플릿에 있으면 그대로 유지) — "기능"이 아니라 **"기둥"** 잡기 (실제 production 템플릿 표기)
- 맨 위 안내 줄(━━━ + "체계 국어 해설 — 구조 스켈레톤" + ━━━)은 **삭제**

## 5. 문단/문제 개수 조정

- 지문 문단이 3개보다 **많으면** → `[3문단]` 블록 복제해서 `[4문단]`, `[5문단]` 추가
- 지문 문단이 3개보다 **적으면** → 남는 `[N문단]` 블록 삭제
- 각 문단 내 문장 개수도 1문장/2문장/3문장 블록 복제·삭제로 조정
- 문제 2개보다 **많으면** → `[문제 2번]` 블록 복제해서 `[문제 3번]`, `[문제 4번]` 추가
- 문제 2개보다 **적으면** → 남는 `[문제 N번]` 블록 삭제

## 6. HWPX 파일 처리 (Python)

- `zipfile`로 템플릿 열기 → `Contents/section0.xml` 파싱(`lxml` 권장) → 본문 자리표시자를 실제 내용으로 교체 → `zipfile`로 재패키징
- **재패키징 시**:
  - `mimetype` 파일은 `ZIP_STORED` (무압축) **+ 첫 번째 항목**
  - 나머지는 `ZIP_DEFLATED`
- **푸터(꼬리말)** 영역 텍스트 런을 찾아 **교재명**으로 교체
- **시작 페이지**는 `secPr`의 `startNum` 또는 `hp:pagePr` 관련 속성으로 조정

## 7. 자리표시자 → 실제 내용 교체 매핑

| 템플릿 자리표시자 | 실제 내용 |
|---|---|
| `(원문 N문장)` | 실제 원문 |
| `● (기의 변환)` | 실제 ● 기의 변환 (불릿 기호 유지) |
| `(흐름 코멘트 — 빨강)` | 실제 흐름 코멘트 |
| `① (선지 내용) → O/X` | 실제 선지 + 판단 |
| `근거: [N문단 N문장] "..."` | 실제 근거 |
| `→ (일치/불일치 설명)` | 실제 설명 |
| `발문 분석: (...)` | 실제 발문 분석 |
| `(지문과 선지의 차이 한 줄 정리)` | 실제 한 줄 정리 |
